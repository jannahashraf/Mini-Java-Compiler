1 Overview

This documentation covers Phase 1 of the Mini Java compiler: a hand-written lexical analyzer (scanner) that turns Mini Java source text into a stream of tokens and builds a symbol table of user-defined identifiers.

No third-party or ready-made lexer/parser libraries are used. The only runtime dependency is the Python standard library (Python 3.10+).

1.1 Quick start

# Scan a sample program; tokens go to stdout.
python3 main.py tests/sample1.mj

# Run the unit and CLI tests.
python3 -m unittest discover -s tests -v

# Run the whole-lexer integration tests.
python3 -m unittest discover -s tests/integration -v

1.4 One-paragraph summary

main.py reads a source file and constructs a Lexer. The lexer walks the source one character at a time, tracking pos, line, and col. Its main loop skips whitespace, delegates comments, identifiers/keywords, numbers, strings, operators, and delimiters to small helper modules, and appends a Token for each lexeme it recognizes. Identifiers are also inserted into a SymbolTable, which keeps the first occurrence of each name. Lexical errors are recorded and printed to stderr by a shared LexerErrorReporter without aborting the scan. When the source is exhausted, the lexer appends a final EOF token and returns the complete token list.

2 Architecture

The lexer is a single-pass, character-oriented scanner. main.py reads the whole source file into a string, builds one Lexer, and asks it for a token list. All scanning is done by the Lexer plus small helper functions that receive the lexer as their context object.

2.1 Pipeline

source file
    |
    v
main.py  (read UTF-8 text)
    |
    v
Lexer.scan_tokens()
    |
    +--> whitespace .................. advance()
    +--> // or /* .................... comments.skip_comment()
    +--> letter or _ ................. identifiers.scan_identifier_or_keyword()
    +--> digit ....................... literals.scan_number()
    +--> ' or " ...................... literals.scan_string()
    +--> anything else ............... operators.scan_operator_or_delimiter()
    |
    v
tokens: list[Token]   +   symbol_table: SymbolTable   +   reporter.errors

Every successful helper call consumes characters through Lexer.advance() and usually calls Lexer.emit(...). Comments and whitespace produce no token. Errors are reported through Lexer.reporter and scanning continues.

2.2 Module responsibilities

Module Responsibility
main.py Parse CLI arguments, read the source file, create a Lexer, print tokens, map errors to an exit code.
src/tokens.py Shared TokenType enum and Token dataclass. This is the contract between all modules.
src/scanner.py Lexer class: source text, cursor position, line/column tracking, token collection, main loop, and dispatch.
src/keywords.py KEYWORDS dictionary mapping reserved words to token types.
src/identifiers.py scan_identifier_or_keyword(): consume an identifier, classify it as keyword or IDENTIFIER, update the symbol table.
src/symbol_table.py SymbolTable: first occurrence of each user-defined identifier, keyed by lexeme.
src/literals.py scan_number() and scan_string(): numeric and quoted-string literals, including invalid forms.
src/operators.py scan_operator_or_delimiter(): longest-match operators, delimiters, and unknown-character errors.
src/comments.py skip_comment(): // line comments and non-nesting /* ... */ block comments.
src/errors.py LexerErrorReporter: format, record, and print lexical diagnostics.

2.3 The Lexer as shared context

The helpers are plain functions rather than subclasses or separate scanners. Each one receives the active Lexer and uses the same public surface:

  • lexer.current() — current character, or "" at end of input.
  • lexer.peek(offset=1) — look ahead without consuming.
  • lexer.advance() — consume one character and update line/column.
  • lexer.at_end() — whether the cursor is past the last character.
  • lexer.emit(type, lexeme, line, col) — append a token and return it.
  • lexer.reporter — shared error reporter.
  • lexer.symbol_table — shared symbol table.

Because every helper consumes text through advance(), source positions remain consistent even when large comments or strings are skipped.

2.4 Character reader

The reader is index-based:

Member Meaning
source The complete input string.
pos Index of the next character to consume.
line 1-based current line.
col 1-based current column.

advance() returns the current character, increments pos, and updates position. A \n increments line and resets col to 1; every other character (including \r) increments col. current() and peek() return "" past the end so callers can compare without bounds checks.

2.5 Main loop and dispatch

Lexer.scan_tokens() repeatedly inspects current() and chooses a helper in a fixed priority order:

  1. Whitespace (" \t\r\n"): consumed one character at a time.
  2. Comments: only when the current character is / and the next is / or *. This check happens before operators so / is reserved for division unless it starts a comment.
  3. Identifiers/keywords: ch.isalpha() or ch == "_".
  4. Numbers: ch.isdigit().
  5. Strings: current character is " or '.
  6. Operators/delimiters/everything else: delegated to the operator helper, which also reports unknown characters.

After the loop ends, the lexer appends Token(TokenType.EOF, "", line, col). EOF is always present exactly once, even when errors occurred.

2.6 Scanning algorithms

2.6.1 Identifiers and keywords

scan_identifier_or_keyword() records the start position, consumes a run of isalnum() or _ characters, then looks up the exact lexeme in KEYWORDS. A hit emits the mapped token type; otherwise it emits IDENTIFIER and inserts the token into the symbol table. Lookup is case-sensitive (class is a keyword, Class is an identifier). main, true, and false are handled by the same table (MAIN and BOOLEAN_LITERAL).

2.6.2 Numbers

scan_number() consumes digits, then optionally a single decimal point followed by at least one digit. It then detects invalid continuations:

  • a trailing . with no following digit → invalid number literal error;
  • a second . → consume the malformed run and report invalid number literal;
  • a letter or _ after the digits → consume the whole run and report invalid identifier (for example 1name or 2_name).

Signs are not part of a number: -5 scans as MATHOP then NUMBER. Exponents and hexadecimal forms are not supported.

2.6.3 Strings

scan_string() remembers the opening quote, then consumes until the same quote character. Single- and double-quoted strings are both accepted. There is no escape processing; a backslash is ordinary text. If EOF is reached first, the helper reports unclosed string literal starting at the opening position and emits no token. Newlines inside an unfinished string are still consumed and advance the line counter.

2.6.4 Comments

The main loop calls skip_comment() only when / is followed by / or *. The helper records the opening position and consumes the two-character opener.

  • //: consume until \r, \n, or EOF. The line ending is left for the main loop’s whitespace handling.
  • /* ... */: consume until the first */, including it. Block comments do not nest, matching Java. If EOF is reached, report unclosed comment starting once at the opening position; the cursor remains at EOF.

2.6.5 Operators and delimiters

scan_operator_or_delimiter() builds the two-character candidate current() + peek(). It checks the two-character operator table first (>=, <=, ==, !=), then the one-character operator table, then the delimiter table. Anything unmatched is consumed and reported as invalid character '<ch>'. This longest-match order is what makes >= one LOGOP instead of > followed by =.

2.7 Complexity

Scanning is one pass over the input. Each character is consumed at most once and lookups use dictionaries, so time is O(n) in the source length. Auxiliary space is O(t) for the token list, O(s) for the symbol table (distinct identifiers), and O(e) for recorded errors. Helpers use loops, not recursion, so very large comments and strings do not hit recursion limits.

2.8 Phase boundaries

This project implements only lexical analysis. It does not parse grammar, type-check, or generate code. The token stream and first-occurrence symbol table are the hand-off points intended for later phases (parsing and semantic analysis). See Data Structures and Token Reference for their exact shapes.

3 Data Structures

The scanner uses a small set of types: one enum for token categories, one token record, one central mutable lexer object, one symbol table, one error collector, and several constant lookup dictionaries.

3.1 TokenType (enum)

src/tokens.py defines TokenType with auto() values. The enum is the shared contract: every helper and test refers to these names, so adding, renaming, or removing a member affects the whole project.

Members grouped by purpose:

Group Members
Keywords CLASS, PUBLIC, STATIC, VOID, INT, FLOAT, BOOLEAN, CHAR, STRING_TYPE, IF, ELSE, WHILE, FOR, RETURN, MAIN
Identifiers and literals IDENTIFIER, NUMBER, STRING, BOOLEAN_LITERAL
Operators ASSIGN, MATHOP, LOGOP
Delimiters LPAR, RPAR, LCUR, RCUR, LSQU, RSQU, SEMICOLON, COMMA, DOT
Bookkeeping EOF, ERROR

ERROR exists in the contract but the current scanner does not emit it: errors are reported as diagnostics instead. EOF is always emitted as the final token.

3.2 Token (dataclass)

@dataclass
class Token:
    type: TokenType
    lexeme: str
    line: int
    col: int

    def __str__(self) -> str:
        return f"Lexeme: {self.lexeme}, Token: {self.type.name}"
Field Type Meaning
type TokenType Classified category.
lexeme str Exact source text that produced the token (for EOF, "").
line int 1-based line of the token’s first character.
col int 1-based column of the token’s first character.

Because it is a regular dataclass, equality compares all four fields and the generated repr is available for debugging. str(token) is the CLI output format, for example Lexeme: class, Token: CLASS.

For string tokens the lexeme retains the quotes ("Ali", 'A'). For numbers it is the original spelling (85.5, not a parsed float).

3.3 Lexer (central state)

Defined in src/scanner.py. One instance scans one source string.

Attribute Type Purpose
source str Entire input text.
pos int Index of the next character to read.
line int Current 1-based line. Starts at 1.
col int Current 1-based column. Starts at 1.
reporter LexerErrorReporter Collects and prints diagnostics.
symbol_table SymbolTable First occurrences of user identifiers.
tokens list[Token] Tokens emitted during the scan.

Key methods:

Method Description
current() -> str Returns source[pos], or "" at/after end.
peek(offset=1) -> str Returns source[pos + offset], or "" out of range.
advance() -> str Consumes and returns the current character; updates line/col.
at_end() -> bool pos >= len(source).
emit(type, lexeme, line, col) -> Token Constructs a Token, appends it to tokens, and returns it.
scan_tokens() -> list[Token] Runs the main loop and appends EOF.

Invariants and behavior:

  • 0 <= pos <= len(source).
  • line starts at 1; col starts at 1 for each line.
  • advance() on \n increments line and resets col = 1; all other characters increment col. \r therefore does not start a new line itself.
  • scan_tokens() appends exactly one EOF token at the end, directly to tokens rather than through emit(). Repeated calls would append additional EOF tokens because the cursor is already at the end; callers use it once.
  • tokens, reporter.errors, and symbol_table are all readable after the scan for tests or later compiler phases.

3.4 SymbolTable

Defined in src/symbol_table.py. It stores user-defined identifier names, not keywords or main/true/false.

class SymbolTable:
    def __init__(self) -> None:
        self._symbols: dict[str, Token] = {}

    def insert(self, token: Token) -> None: ...
    def lookup(self, name: str) -> Token | None: ...
    def __len__(self) -> int: ...
Member Behavior
_symbols Private dict[str, Token] keyed by lexeme.
insert(token) Stores only the first token for each lexeme; later occurrences are ignored.
lookup(name) Returns the stored first token, or None.
len(table) Number of distinct names.

Design notes:

  • It is a flat, single-scope table. There is no nesting, shadowing, or type information yet; those belong to later phases.
  • The stored Token includes the location of the first occurrence, which is why duplicates are deliberately not overwritten.
  • Dictionary insertion order preserves first-seen order if later phases need to enumerate symbols.

3.5 LexerErrorReporter

Defined in src/errors.py.

class LexerErrorReporter:
    def __init__(self) -> None:
        self.errors: list[str] = []

    def error(self, message: str, line: int, col: int) -> None: ...
    def has_errors(self) -> bool: ...
Member Behavior
errors Formatted diagnostic strings in encounter order.
error(...) Formats Error: <message> at line <line>, column <col>., appends it, and prints it to stderr immediately.
has_errors() True when errors is non-empty.

The reporter does not raise exceptions. It is normally one instance per Lexer, so separate scans do not share errors. See Error Handling for the full contract.

3.6 Lookup tables

All lookup tables are module-level constants, created once at import time.

3.6.1 KEYWORDS

dict[str, TokenType] in src/keywords.py, keyed by exact, case-sensitive lexeme. It also maps main to MAIN and true/false to BOOLEAN_LITERAL. See Token Reference for the complete list.

3.6.2 Operator and delimiter tables

src/operators.py defines three dictionaries:

Constant Key type Value Checked
TWO_CHAR_OPERATORS str (2 chars) LOGOP for >=, <=, ==, != First
ONE_CHAR_OPERATORS str (1 char) ASSIGN for =, MATHOP for + - * / %, LOGOP for > < ! Second
DELIMITERS str (1 char) Parentheses, braces, brackets, ;, ,, . Third

Checking two-character operators first implements longest match.

3.7 How the structures fit together

Lexer.source ──(reader)──> current/peek/advance
                                |
                                v
                    helper consumes characters
                                |
                                v
                    Lexer.emit(type, lexeme, line, col)
                                |
                                +--> Lexer.tokens : list[Token]
                                |
                                +--> Lexer.symbol_table (identifiers only)

helper on bad input ──> Lexer.reporter.error(...)
                                |
                                +--> reporter.errors : list[str] -> stderr

The CLI prints each Token with str(token) and uses reporter.has_errors() to choose the process exit status.

4 Token Reference

This is the complete token vocabulary produced by the Phase 1 lexer. Token names come from TokenType in src/tokens.py.

4.1 Token categories

Category Token types Lexemes
Keywords CLASS, PUBLIC, STATIC, VOID, INT, FLOAT, BOOLEAN, CHAR, STRING_TYPE, IF, ELSE, WHILE, FOR, RETURN, MAIN See keyword table below.

4.2 Keywords

Mini Java is case-sensitive and keyword lookup is exact. The mapping lives in src/keywords.py.

Lexeme Token type
class CLASS
public PUBLIC
static STATIC
void VOID
int INT
float FLOAT
boolean BOOLEAN
char CHAR
String STRING_TYPE
if IF
else ELSE
while WHILE
for FOR
return RETURN
main MAIN
true BOOLEAN_LITERAL
false BOOLEAN_LITERAL

Consequences of case sensitivity:

  • class is CLASS, but Class is IDENTIFIER.
  • String is STRING_TYPE, but string is IDENTIFIER.
  • main is MAIN, but Main is IDENTIFIER.
  • true/false are BOOLEAN_LITERAL, but True/FALSE are IDENTIFIER.
  • The type keyword boolean (BOOLEAN) is distinct from the values true/false (BOOLEAN_LITERAL).

4.3 Identifiers

An identifier:

  • starts with a letter (str.isalpha()) or underscore _;
  • continues with letters, digits (str.isalnum()), or _;
  • is not a reserved word.

Examples: age, studentName, x1, _count, total_marks.

The implementation uses Python’s Unicode-aware isalpha/isalnum predicates, so non-ASCII letters are accepted even though the language is intended for ASCII identifiers. Only lexemes classified as IDENTIFIER are added to the symbol table.

4.4 Numeric literals

NUMBER covers integers and simple decimal floats:

  • 0, 10, 2026 — integers;
  • 25.5, 0.5 — floats with digits on both sides of the dot.

Not supported (and reported as lexical errors):

  • a trailing dot such as 5. → invalid number literal;
  • more than one dot such as 1.2.3 → invalid number literal;
  • a digit-run followed by a letter or _ such as 1name or 2_name → invalid identifier.

The lexeme is the original source spelling; numbers are not converted to int/float at this phase. A leading - or + is a separate operator token, so -5 is MATHOP followed by NUMBER. Exponents, hex, underscores in numerals, and suffixes are not part of the language.

Note that .5 begins with ., which dispatches to the delimiter helper, so it becomes DOT followed by NUMBER rather than a single float.

4.5 String literals

STRING accepts either delimiter style:

  • double-quoted: "Hello", "Ali", "";
  • single-quoted: 'A', '//', ''.

The lexeme includes the surrounding quotes. There is no escape processing: a backslash is an ordinary character and cannot escape the closing quote. A string may span lines. If EOF is reached before the matching quote, the scanner reports unclosed string literal starting at the opening quote and emits no STRING token.

Comment markers inside strings are literal text, e.g. "http://host/*path*/" is one STRING token.

4.6 Operators

Operators use longest match: two-character operators are tested before one-character operators.

Lexeme Token type Notes
>= LOGOP Two-character match.
<= LOGOP Two-character match.
== LOGOP Two-character match.
!= LOGOP Two-character match.
> LOGOP Single character.
< LOGOP Single character.
! LOGOP Single character.
= ASSIGN Assignment only; == is comparison.
+ MATHOP
- MATHOP
* MATHOP
/ MATHOP Division, unless followed by / or * for a comment.
% MATHOP

Compound assignment (+=), increment/decrement (++, --), and bitwise operators are not defined; they would scan as separate tokens or errors.

4.8 Whitespace and comments

Whitespace (space, \t, \r, \n) is skipped and produces no token.

Comments produce no token:

  • // ... until end of line or EOF;
  • /* ... */ until the first */; block comments do not nest.

An unterminated block comment produces a diagnostic at its opening position, not a token. See Error Handling.

4.9 End of file and errors

  • EOF has lexeme "" and is appended exactly once after scanning. Its line/col are the position after the last consumed character.
  • ERROR is declared for the contract but unused. Lexical problems are reported through LexerErrorReporter and the scanner continues; the offending text generally produces no token.

5 Error Handling

Lexical errors are diagnostics, not exceptions. The scanner records the problem, keeps going where possible, and still produces a token stream ending in EOF.

5.1 The reporter

All helpers call the same method:

lexer.reporter.error(message, line, col)

LexerErrorReporter.error():

  1. formats the message as Error: <message> at line <line>, column <col>.;
  2. appends the formatted string to reporter.errors in encounter order;
  3. prints the same string to stderr immediately.

So helpers pass only the bare message (for example invalid character '@') and the starting position. The prefix Error:, the location phrase, and the final period are added centrally.

Streams are separated deliberately: tokens are printed to stdout by the CLI and diagnostics go to stderr. reporter.errors is available for programmatic checks and tests.

5.2 Position conventions

  • line and col are 1-based.
  • Reported positions refer to the start of the offending construct, not the point where the error is detected. For example, an unclosed comment reports the opening /*, and an unclosed string reports the opening quote.
  • col counts characters, not bytes. A \n resets the column; \r counts as a normal character.

5.3 Diagnostic kinds

The scanner produces four required diagnostic forms.

Situation Message passed to the reporter Typical output
Unknown character invalid character '@' Error: invalid character '@' at line 1, column 12.
Digit-started invalid name invalid identifier '1name' Error: invalid identifier '1name' at line 1, column 1.
EOF inside a string unclosed string literal starting Error: unclosed string literal starting at line 1, column 15.
EOF inside a block comment unclosed comment starting Error: unclosed comment starting at line 1, column 1.
Malformed number invalid number literal '5.' Error: invalid number literal '5.' at line 1, column 1.

The first four are exercised by dedicated fixtures in tests/fixtures/errors/. The malformed-number diagnostic has no separate fixture but is implemented in scan_number() and can be triggered with input such as 5. or 1.2.3.

5.4 Recovery behavior by helper

5.4.1 Unknown character (operators.py)

The character is consumed, then the error is reported. Scanning resumes at the next character, so later tokens are still produced. For example, in int x = 10 @ 5; the error is recorded but 5 and ; still scan normally.

5.4.2 Malformed number / invalid identifier (literals.py)

scan_number() consumes the malformed run and reports one error, emitting no token for it:

  • trailing dot (5.) or second dot (1.2.3) → invalid number literal;
  • letter/underscore after digits (1name, 2_name) → invalid identifier.

Consuming the whole run avoids producing misleading partial tokens such as 1 followed by name.

5.4.3 Unclosed string (literals.py)

The helper consumes to EOF looking for the closing quote, reports once at the opening quote, and emits no STRING token. Because the rest of the file is treated as string contents, any comments or errors after the opening quote are not scanned separately.

5.4.4 Unclosed block comment (comments.py)

The helper consumes to EOF, reports once at the opening /*, and leaves the cursor at EOF. The main loop then appends EOF. Block comments do not nest, so the first */ always closes; an opener inside a comment is just text.

5.4.5 Line comments

A // comment has no error condition: it ends at a line ending or EOF.

5.5 Multiple errors

Reporting does not stop the scan, so several independent errors can be collected in one run. Order in reporter.errors matches source order of detection. Some constructs can swallow later input, however:

  • an unclosed string consumes everything to EOF;
  • an unclosed block comment consumes everything to EOF.

For that reason tests/sample_errors.mj (which mixes an invalid symbol, an invalid identifier, an unclosed string, and an unclosed comment) is not used to verify all four diagnostics together; the independent fixtures are. An unclosed string before a block comment prevents the comment from being scanned as code.

5.6 Reporter lifetime

A fresh Lexer creates a fresh LexerErrorReporter. Reporters do not share state, so scanning one file cannot leak diagnostics into another. has_errors() is simply bool(self.errors).

5.7 CLI exit status

main.py maps the scan result to an exit code:

Code Meaning
0 File scanned successfully; no lexical errors.
1 One or more lexical errors were reported.
2 Incorrect command-line usage (not exactly one source-file argument).

Tokens (including EOF) are still printed to stdout when the exit code is 1; diagnostics are on stderr. Usage errors print the usage line to stdout and return 2.

6 Testing

Tests use Python’s standard-library unittest and exercise the real lexer, reader, reporter, and CLI. No replacement implementations or optional skips are used.

Run all commands from the repository root.

6.1 Test suites

6.1.1 Unit and CLI checks — 18 tests

python3 -m unittest discover -s tests -v
File Tests Focus
tests/test_comments.py 11 Line and block comment boundaries, CRLF, nesting behavior, EOF handling, large blocks, comment-only fixtures.
tests/test_errors.py 4 Exact diagnostic format, encounter order, stderr-only output, reporter isolation.
tests/test_cli.py 3 Comment-only success, unclosed-comment failure, missing-argument usage error.

Notable assertions:

  • Line comments stop before \n, \r, or \r\n, leaving the line ending to the main loop; block comments close at the first */.
  • Comments emit no tokens, do not populate the symbol table, and do not scan code-like contents.
  • Unterminated blocks report exactly once at the opening position and leave the cursor at EOF.
  • A 10,000-line block comment scans without recursion.
  • Diagnostics are identical in reporter.errors and stderr, and separate reporters do not share errors.
  • CLI exit codes are 0 (success), 1 (lexical errors), and 2 (usage).

6.1.2 Whole-lexer integration checks — 13 tests

tests/integration/test_lexer.py runs against the complete scanner and covers:

  • The specification sample matches tests/expected_output.txt byte for byte.
  • Every keyword and boolean literal, plus case-sensitive identifier fallbacks (Class, string, Main, True, FALSE).
  • Symbol-table first-occurrence semantics and stored positions.
  • Integer, float, single-quoted, double-quoted, and empty strings.
  • Longest-match operators and all delimiters with correct columns.
  • Comments as token separators while / remains division.
  • Comment markers inside strings staying literal.
  • Three programs in sample_programs.mj covering every TokenType except ERROR.
  • All four error fixtures with exact messages and positions.
  • Invalid identifiers such as 2_name and recovery after an unknown character.
  • End-to-end CLI output equal to the golden file.

tests/integration/ is specified explicitly as a discovery directory, so it is not included in the first command.

6.2 Fixtures

Input Purpose
tests/sample1.mj Specification example.
tests/expected_output.txt Golden token stream for sample1.mj, including EOF.
tests/sample_programs.mj Three programs covering all token categories except ERROR.
tests/comments_only.mj Comment-only smoke test; only EOF is emitted.
tests/sample_errors.mj Mixed-error example; useful for manual inspection but not for isolating all four diagnostics.
tests/fixtures/errors/invalid_symbol.mj @ at line 1, column 12.
tests/fixtures/errors/invalid_identifier.mj 1name at line 1, column 1.
tests/fixtures/errors/unclosed_string.mj Opening quote at line 1, column 15.
tests/fixtures/errors/unclosed_comment.mj Opening /* at line 1, column 1.

The fixtures are intentionally separate because an unclosed string consumes the rest of the file, which would hide a later unclosed-comment error.

6.3 Manual checks

# Successful scan; tokens on stdout.
python3 main.py tests/sample1.mj

# Comment-only input; prints only the EOF token, exits 0.
python3 main.py tests/comments_only.mj

# Error input; prints EOF on stdout and one diagnostic on stderr, exits 1.
python3 main.py tests/fixtures/errors/unclosed_comment.mj

# Usage error; exits 2.
python3 main.py

6.4 Adding tests

  • Put unit tests at the top level of tests/ so the first discovery command finds them. Put full-scanner tests under tests/integration/.
  • Import from src.* (for example from src.scanner import Lexer) and run from the repository root.
  • Redirect stderr with contextlib.redirect_stderr(io.StringIO()) when a test intentionally triggers diagnostics, so test output stays clean.
  • Assert lexer.reporter.errors for exact messages and token.type/lexeme for classification.
  • Remember that every successful scan ends with exactly one EOF token; use tokens[:-1] when comparing token sequences.

7 Usage

7.1 Requirements

  • Python 3.10 or newer.
  • No third-party packages.

7.2 Command line

python3 main.py <source-file>

main.py reads exactly one file as UTF-8, scans it, and prints one line per token to stdout:

Lexeme: <lexeme>, Token: <TOKEN_TYPE>

Lexical diagnostics are printed to stderr. The final token is always EOF, whose lexeme is empty:

Lexeme: , Token: EOF

Example:

python3 main.py tests/sample1.mj

Output begins:

Lexeme: class, Token: CLASS
Lexeme: Student, Token: IDENTIFIER
Lexeme: {, Token: LCUR
Lexeme: public, Token: PUBLIC
Lexeme: static, Token: STATIC
Lexeme: void, Token: VOID
Lexeme: main, Token: MAIN
...
Lexeme: , Token: EOF

7.3 Exit codes

Code Meaning
0 Scan completed with no lexical errors.
1 At least one lexical error was reported. Tokens are still printed.
2 Wrong number of command-line arguments; a usage line is printed.

Example of an error run:

python3 main.py tests/fixtures/errors/unclosed_comment.mj

stdout:

Lexeme: , Token: EOF

stderr:

Error: unclosed comment starting at line 1, column 1.

exit status: 1.

7.4 Programmatic use

from src.scanner import Lexer
from src.tokens import TokenType

source = 'int age = 20;'
lexer = Lexer(source)
tokens = lexer.scan_tokens()

for token in tokens:
    print(token.type.name, repr(token.lexeme), token.line, token.col)

if lexer.reporter.has_errors():
    print("errors:", lexer.reporter.errors)

print("symbols:", len(lexer.symbol_table))
print("age at:", lexer.symbol_table.lookup("age"))

This prints the token stream, then reports the number of distinct identifiers and the first age token. scan_tokens() is normally called once per lexer.

7.5 What the scanner does not do

Phase 1 is lexical analysis only:

  • It does not parse statements or expressions.
  • It does not validate that tokens form a grammatical program.
  • It does not assign types or check declarations.
  • It does not evaluate literals; NUMBER lexemes remain strings.

The outputs intended for later phases are lexer.tokens (the stream) and lexer.symbol_table (first occurrence of each user-defined identifier).
